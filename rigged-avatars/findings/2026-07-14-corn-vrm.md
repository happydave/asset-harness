# Findings: VRM export walking skeleton (corn-person → VRM 1.0 + 0.x)

**Date:** 2026-07-14
**Track:** rigged-avatars
**Verdict:** works

## Goal

Prove the **entire VRM export chain** on the existing rigid corn-person — VRM humanoid bone mapping, meta,
dual **VRM 1.0 + 0.x** emit, a spring-bone chain, and the `.glb` game-lane fallback — **with no skinning
and no shape keys**, so the chain is verified before the WI 926 kill-shot exercises skinning + morphs.
(asset-harness WI 925; the "step 0 walking skeleton" of the WI 923 VTuber ladder.)

## Tooling

- **Blender 4.2.22 LTS** + **saturday06 VRM Add-on v4.4.0** (extension format), installed home-dir on
  `ai2` (WI 933) at `~/blender-4.2/blender`. The system `/usr/bin/blender` (4.0.2) has no add-on.
- **New:** `rigged-avatars/prototypes/vrm_export.py` — a reusable helper (the shared exporter the
  two-archetype design reuses): humanoid slot map (19 bones → VRM 1.0 slots + VRM 0.x names), clean-lane
  meta, one spring chain, `export_scene.vrm` dual 1.0/0.x emit.
- **`blender_corn.py --vrm`** — adds a 2-joint `tuft` bone chain (re-parents the cob husk-tuft cones onto
  the swaying tip) and calls the helper, alongside the existing `corn.glb`.
- Headless: `~/blender-4.2/blender -b --python blender_corn.py -- --out DIR --vrm`.

## Result

- **Samples:** [`samples-2026-07-14-vrm/`](samples-2026-07-14-vrm/) — `corn.vrm` (1.0), `corn.vrm0.vrm` (0.x).
- **What worked:**
  - **Dual emit** from one run: `corn.vrm` (VRMC_vrm + VRMC_springBone) + `corn.vrm0.vrm` (VRM).
  - **19-bone humanoid map, no re-rig** — all 15 required VRM slots + chest/neck/shoulders, from the
    existing `corn_bone_defs` names (the add-on writes name→node-index; our Blender names are irrelevant).
  - **Meta** complete on both specs (required 1.0 `name`/`authors`/`licenseUrl` present; the add-on
    auto-supplies the VRM licence URL).
  - **Spring chain** `tuft` with 2 joints + a **`center`** node (the anti-explosion tool).
  - **Two artifacts, one source scene:** the VRMs **drop** animation clips (`animations=0`) by convention;
    the game-lane `corn.glb` **keeps** its `walk`/`idle` clips. This early-answers a WI 926 question.
  - **Rigid bone-parented meshes export as valid VRM** — confirming skinning is not required for VRM, so
    the whole export chain is verified *before* WI 926 touches skinning.
  - Both VRMs **re-import** cleanly through the add-on.
- **What was deferred (F1/F2, minor):**
  - **F1 — head sphere collider:** raw-property colliders don't export (the add-on needs its
    `vrm.add_spring_bone1_collider` operator to back the collider with an Empty); dropped, since it adds
    little for an upward tuft. The spring + `center` (the anti-explosion essential) are present.
  - **F2 — VRM 0.x hair spring:** only VRM 1.0 `spring_bone1` is populated; 0.x `secondaryAnimation` is
    empty, so the tuft doesn't sway in a 0.x/VSeeFace path (0.x still carries full humanoid + meta).

## Repeatability

- Deterministic; parametric build. Non-`--vrm` runs are unchanged (`add_tuft_chain` runs only under `--vrm`).
- **Gotcha recorded:** `read_factory_settings` (which `build_corn` calls) **disables** the VRM add-on and
  drops its preferences; `vrm_export.ensure_addon()` re-enables with `addon_utils.enable(..., default_set=True)`.

## [visual/manual] — owner gate (B8)

Load `corn.vrm` in a browser three-vrm viewer and confirm the humanoid poses correctly (authored
**arms-down / I-pose**, not T-pose — expected for this walking skeleton; a canonical T-pose belongs to the
real rig, WI 923 ladder step 5) and the head tuft **sways**. Load `corn.vrm0.vrm` in a 0.x path (VSeeFace).
