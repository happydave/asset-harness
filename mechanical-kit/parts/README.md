# Rover part-mesh catalog (v1) — for Sounding `Part` / WI 608

Integration artifacts for the Sounding session to retrieve. Generated by
[`../prototypes/blender_parts.py`](../prototypes/blender_parts.py) (parametric Blender, headless on
`ai2`); regenerate with:

```
# 1. geometry (parametric solids, base material factors, origin/orientation)
scp prototypes/blender_parts.py ai2:/tmp/ && \
ssh ai2 'cd /tmp && blender --background --python blender_parts.py -- --out /tmp/mk_parts --cell-size 0.5'
# 2. AI-PBR skin (needs the material library: rsync prototypes/materials/ → ai2:/tmp/mk_mat)
scp prototypes/blender_texture_parts.py ai2:/tmp/ && \
ssh ai2 'cd /tmp && blender --background --python blender_texture_parts.py -- --in /tmp/mk_parts --materials /tmp/mk_mat --out /tmp/mk_parts_tex'
scp ai2:/tmp/mk_parts_tex/'*' parts/
```

Both scripts take `--only <names>` to (re)build a subset.

## Contract (read from `crates/sim/src/{voxel,rover}.rs`)

- **Frame:** `+Y` up, `+Z` forward, `+X` lateral (the wheel axle); steering is about `+Y`.
- **Origin:** each mesh's origin is its **mount point** — what `Part.mount` (metres, lattice frame)
  positions. Drop the mesh at `Part.mount` with identity rotation and it sits correctly.
- **Units:** metres. **glTF Y-up.** Sized for `cell_size = 0.5 m`; regenerate with `--cell-size` to
  match the build (dimensions scale linearly).
- See [`manifest.json`](manifest.json) for per-part origin / orientation / material / vert count.

## Parts

**Rover** — `tire`, `rim`, `suspension` (a wheel station = these three, WI 630, sharing the
hub-centre mount), `seat`, `antenna`, `solar_panel`, `bumper`; variants `seat_leather`,

**Fittings** (wall fittings face +Z, origin at the hull-mount centre) — `hatch_round`, `hatch_rect`,

## Surfaces

Geometry embeds PBR **material factors**; the shipped glbs are then **AI-textured** via the
`pbr-materials` track (albedo + tangent normal + packed metallic-roughness, 256 px embedded) by
`blender_texture_parts.py`. Sounding may still apply its own material at import.

## Split parts (WI 666)

Most parts ship as one joined mesh. **Split parts** instead export a named node hierarchy under an
Empty root at the mount origin, with per-piece materials and a role tag in each node's glTF
`extras`. The **battery** is the reference: root `battery` → `battery_body`, `battery_lid` (plastic),
`battery_terminal_pos`, `battery_terminal_neg` (metal); terminals carry `polarity`. See the
`subparts` list in [`manifest.json`](manifest.json). Sounding loads these transparently (the whole
glb scene is instantiated). To split another part: build its pieces separately and call
`export_group` in `blender_parts.py`, and add a `SPLIT_SKIN` entry in `blender_texture_parts.py`.
