# VLM-as-judge for still selection — tested, does not earn promotion (WI 1179)

**Date:** 2026-08-28 · **Track:** music-video · **Verdict:** neither selection nor shortlist ordering

The one scorer type the WI 989 survey named and nobody had tested, and the only one that can be handed
the written brief. Scored **retrospectively** against archived owner rankings — no new generation, no
owner time. Full record: [WI 1179 spike](../../../../tickets/docs/pending/1179-ah-music-video-vlm-judge-spike/spike.md).

## Result

Two models — `Qwen/Qwen3-VL-8B-Instruct-GGUF` Q8_0 and `Qwen3-VL-32B-Instruct` Q4_K_M, both
**apache-2.0**, both run locally on `ai2` through the llama.cpp already installed there (~6–25 s per
group) — across three protocols and two corpora:

| | corpus A rho (n=5×2) | corpus A top-1 | corpus B top-1 (n=3×6) |
|---|---|---|---|
| Qwen3-VL-8B listwise | −0.20 | 0/2 | 0/6 |
| Qwen3-VL-8B pairwise | −0.30 | 0/2 | 2/6 |
| Qwen3-VL-8B pointwise | −0.60 | 0/2 | 2/6 |
| Qwen3-VL-32B listwise | +0.05 | 0/2 | 2/6 |
| **PickScore letterbox** (baseline) | **+0.30** | 1/2 | **3/6** |
| "always answer the first one" | — | — | **4/6** |

Corpus A = the WI 1037 blind rankings. Corpus B = six WI 1111 scienceranch slots (3 seeds each) with
the owner's shipped pick — held out, never used to calibrate a scorer.

## Three things worth keeping

**1. The gate/selector split is now three-for-three.** Both VLMs place a deliberately off-brief image
**last**, every time, in every protocol — and neither can order candidates that are all on-brief. Same
result as CLIP and PickScore in WI 1037, from a different model family with a different objective,
given the brief the reward models never saw. Machine judgment separates on-brief from garbage and
cannot separate good from better. Cull with it; do not select with it.

**2. Presentation order is a confound with teeth — this is the transferable finding.** Shown the
candidates in the owner's *own ranked order* (the order the archived form records, and the order the
first draft of the harness used without thinking), the 8B judge scores **+0.55 and 2/2 top-1 — beating
the promotion bar** — by answering "1,2,3,4,5". Shuffled so the owner's favourite is never first, the
same model on the same images scores **−0.20 and 0/2**. On corpus B it ranked the first-presented
candidate first in **12 of 12** runs. Any ranking read out of a model — or shown to a human — must
randomise order and report a position control.

**3. The +0.30 bar sits inside its own noise.** At n = 5, rank correlation ≥ +0.30 arises **34%** of the
time by chance (exact permutation null, `vlm_judge.permutation_p`). Quote the p-value beside rho.

## Reuse

- [`scoring/vlm_judge.py`](../prototypes/scoring/vlm_judge.py) — corpora, three protocols
  (listwise / pairwise / pointwise), the controls, Spearman + exact permutation null. Stdlib + ffmpeg,
  talks to any OpenAI-compatible endpoint.
- [`scoring/vlm_report.py`](../prototypes/scoring/vlm_report.py) — the verdict table with every
  comparator beside the result. [`scoring/baseline_corpus_b.py`](../prototypes/scoring/baseline_corpus_b.py)
  — the WI 1045 scorers on corpus B, so challenger and baseline are compared on the same images.
- Raw judge output is committed as `scoring/vlm_[ab]_*.json` (small; the evidence behind the table).

`ai2` was left as found — temporary `llama-server` stopped, 29 GB of weights removed, no service
touched. One trap for anyone re-fetching them: an 8-way parallel range download **must verify each
part's length**. A dropped connection ends a ranged `curl` with exit status 0 and a truncated part, and
`cat` will happily join it — the first 32B attempt produced 17.19 GB of an expected 19.76 GB with no
error anywhere.
